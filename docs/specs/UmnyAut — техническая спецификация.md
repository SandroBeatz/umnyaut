# UmnyAut — техническая спецификация

Oct 7, 2026 · @Aleksandr

UmnyAut строится на Next.js с базой в Supabase: прод работает в Docker на VPS в СНГ, стейджинг — на Vercel. Все расчёты живут в одном пакете на чистом TypeScript, общем для сайта, Telegram-мини-приложения и виджета.

## 1. Резюме

Сайт — обычное приложение Next.js 16 на App Router. Прод работает в Docker на VPS в СНГ и выкладывается из ветки `main`; стейджинг живёт на Vercel и собирается из ветки `develop`. Данные хранятся в Supabase. Остальное определяют семь решений.

1. **Расчёты — отдельный пакет на чистом TypeScript.** `@umnyaut/calc` не знает про React, сеть и базу. Его используют сайт, мини-приложение Telegram, виджет и тесты формул.
2. **Все страницы для поиска генерируются статически.** В HTML уже есть заголовок, текст и результат по типовым значениям. Калькулятор оживает в браузере и считает без запросов к серверу.
3. **Сервер нужен для четырёх задач:** сохранённые проекты, вебхук Telegram, ИИ-распознавание, сообщения об ошибках.
4. **Браузер не обращается к Supabase напрямую.** Запросы идут через наш API; ключ базы есть только на сервере.
5. **Аккаунтов нет до платного режима мастера.** Состояние живёт в адресе страницы и в localStorage, проекты открываются по ссылке.
6. **Один образ для прода, проверенный до выпуска.** Прод — контейнер Next.js за Caddy на VPS. Этот же образ собирается и проходит дымовой тест в CI на каждом PR, а код не использует ничего, что есть только у Vercel.
7. **Один репозиторий:** pnpm и Turborepo, приложение `web`, пакеты `calc`, `catalog`, `ui`, `db`.

**Почему не Cloudflare и не первый попавшийся зарубежный хостинг.** С 9 июня 2025 года российские провайдеры обрывают соединения с сетью Cloudflare после первых 16 КБ; в том же [сообщении](https://habr.com/ru/news/922532/) среди пострадавших названы Hetzner, DigitalOcean и OVH. Россия — крупнейший из четырёх рынков, поэтому прод стоит на VPS в СНГ, а страна и провайдер выбираются замером из четырёх стран (раздел 18).

## 2. Стек

Стек собран под три условия: один разработчик на 8–10 часов в неделю, статические страницы для поиска, одинаковая работа на Vercel и на своём сервере. Версии — последние стабильные на день старта, фиксируются в lock-файле.

| Слой | Технология | Зачем и как используем |
| --- | --- | --- |
| Язык | TypeScript, режим `strict` | Один язык для расчётов, сайта, бота и скриптов |
| Фреймворк | Next.js 16, App Router, React 19.2, React Compiler | Статическая генерация страниц, серверные маршруты API, метаданные и карта сайта из коробки |
| Прод | VPS в СНГ: Docker Compose, Next.js с `output: "standalone"`, Caddy | Ветка `main`. Приложение — один контейнер; Caddy выпускает сертификаты и сжимает ответы |
| Стейджинг | Vercel | Ветка `develop` и превью на каждый PR. Всегда закрыт от индексации |
| Стили | Tailwind CSS 4, тема на CSS-переменных | Быстрая вёрстка, малый CSS, один набор токенов для сайта, мини-приложения и виджета |
| UI-примитивы | shadcn/ui на Radix, выборочно | Диалог, выпадающий список, вкладки, аккордеон, уведомления. Компоненты копируются в `packages/ui` |
| Состояние | Zustand с `persist` | «Моя комната» и настройки в localStorage. Состояние калькулятора — локальный хук, без глобального стора |
| Валидация | Zod | Схемы ввода калькуляторов, тел запросов API и ответов ИИ |
| Схемы раскладки | SVG-компоненты React | Геометрию считает `calc`, компонент только рисует. Без canvas и сторонних библиотек |
| Тексты страниц | Markdown с frontmatter в репозитории | Скрипт сборки превращает их в типизированный модуль. MDX не берём: лишняя зависимость сборки |
| База | Supabase Postgres, `@supabase/supabase-js` только на сервере | Проекты по ссылке, пользователи Telegram, счётчики ИИ, сообщения об ошибках. Миграции — SQL-файлы через Supabase CLI |
| Лимиты запросов | Счётчик в памяти процесса и счётчики в Postgres | Первый отсекает всплески без похода в базу; вторые держат суточные лимиты |
| Фоновая работа | `after()` из Next.js | Действия после ответа: обработка вебхука Telegram, отметка открытия проекта. Одинаково работает на VPS и на Vercel |
| Telegram | grammY в режиме вебхука, официальный `telegram-web-app.js` | Бот — один серверный маршрут; мини-приложение — те же страницы сайта |
| ИИ | Anthropic API за интерфейсом `VisionProvider` | Распознавание этикетки, плана и сметы. Провайдер меняется без правки функций (раздел 13) |
| Аналитика | Яндекс Метрика с Вебвизором после согласия; свои обезличенные счётчики; обёртка `track()` | Все события идут через одну функцию; GA4 подключается позже без правки компонентов |
| Тесты | Vitest, fast-check, Playwright | Эталонные примеры формул, проверка инвариантов, сквозные сценарии на мобильном экране |
| Качество кода | Biome, Steiger, `tsc --noEmit` | Линт и формат одним инструментом; Steiger следит за слоями FSD |
| Репозиторий | pnpm workspaces, Turborepo, Node.js 24 LTS | Кэш сборок и тестов, общие пакеты |
| CI/CD | GitHub Actions, GitHub Container Registry | Проверки на каждый PR, сборка образа, выкладка на VPS из `main` |

**Чего в стеке нет и почему**

- ORM (Prisma, Drizzle): таблиц семь, запросы простые. Хватит `supabase-js` и SQL-функций, которые одинаково работают с VPS и из функций Vercel.
- tRPC, GraphQL, Redux, React Query: серверных маршрутов около десяти, расчёты идут в браузере.
- CMS: тексты пишет один человек, они лежат рядом с кодом и проверяются тем же PR.
- Библиотека i18n: язык один. Страна, валюта и магазины — это конфигурация, а не перевод (раздел 10).
- Клиентский SDK Supabase и Supabase Auth: до платного режима мастера аккаунтов нет.
- CDN, Redis, Kubernetes, своя база на сервере: один сервер без состояния проще обслуживать. CDN с узлами в СНГ добавляется перед Caddy, когда появится нагрузка.

**Тарифы на старте**

| Сервис | Что берём | Ограничение | Цена |
| --- | --- | --- | --- |
| VPS | 2 vCPU, 4 ГБ памяти, 40 ГБ SSD, Ubuntu LTS | Один сервер; данных на нём нет | 0,5–1,5 тыс. ₽ в месяц, оценка из бизнес-спеки |
| Vercel | План Hobby | По условиям Vercel он только для некоммерческих проектов | Бесплатно; план Pro — около $20 в месяц |
| Supabase | План Free, два проекта: `dev` и `prod` | База 500 МБ, проект засыпает после недели без активности ([тарифы](https://supabase.com/pricing)) | Бесплатно; $25 в месяц с запуском платного режима мастера |

Vercel нужен только для проверки перед выпуском, поэтому его лимиты и доступность из России на посетителей не влияют. Если условие о некоммерческих проектах станет помехой, стейджинг переезжает вторым контейнером на тот же VPS.

## 3. Архитектура

Браузер получает готовую страницу и дальше считает сам. К серверу он обращается, чтобы сохранить проект или распознать фото.

Выделенный блок — место, где выполняется расчёт. Счётчик Метрики на схеме не показан: он грузится в браузере после согласия на cookie.

**Что где выполняется**

| Действие | Где выполняется | Нужна ли сеть |
| --- | --- | --- |
| Результат по типовым значениям | При сборке сайта: `calc` + `catalog` + `content` → HTML | Нет |
| Пересчёт при вводе | Браузер, модуль `calc` | Нет |
| Перенос комнаты между инструментами | Браузер, localStorage | Нет |
| Ссылка на расчёт с параметром `s` | Браузер | Нет |
| Сохранение и открытие проекта | Серверный маршрут → Supabase | Да |
| Распознавание фото | Серверный маршрут → Anthropic API | Да |
| «Мои расчёты» в Telegram | Серверный маршрут → Supabase | Да |
| Сообщения бота | Telegram → вебхук → ответ через Bot API | Да |

Следствие для пользователя в магазине: открытая страница инструмента продолжает считать при плохой связи. Следствие для бюджета: число серверных запросов зависит от сохранений и ИИ, а не от посещаемости.

## 4. Репозиторий

Один монорепозиторий: приложение `web` и четыре пакета. Граница между ними — главное архитектурное правило: формулы не зависят от интерфейса, интерфейс не содержит формул.

```text
umnyaut/
├─ apps/
│  └─ web/                 Next.js: сайт, API, мини-приложение, виджет
│     ├─ app/              только маршруты: page.tsx, layout.tsx, route.ts
│     ├─ src/
│     │  ├─ views/         сборка страницы из виджетов (слой pages в FSD)
│     │  ├─ widgets/       calculator-shell, result-panel, room-bar, layout-scheme
│     │  ├─ features/      save-project, share-result, report-error, pick-country, scan-label
│     │  ├─ entities/      room, project, tool, country
│     │  └─ shared/        api-клиент, analytics, lib, config
│     ├─ server/           код только для сервера: db, ai, telegram, limits, platform
│     ├─ content/          Markdown: тексты инструментов, справочник, служебные
│     ├─ e2e/              сценарии Playwright
│     └─ Dockerfile        образ для прода: Next.js standalone
├─ packages/
│  ├─ calc/                формулы, единицы, упаковки, геометрия раскладки
│  ├─ catalog/             реестр инструментов, категории, пресеты, страны
│  ├─ ui/                  дизайн-токены и базовые компоненты
│  └─ db/                  SQL-миграции, типы базы, функции запросов
├─ infra/                  compose.yml, Caddyfile, скрипты подготовки сервера и выкладки
├─ tooling/                общие конфиги: tsconfig, biome, vitest
└─ .github/workflows/
```

**Правила импортов**

| Кто | Может импортировать | Не может |
| --- | --- | --- |
| `calc` | Ничего, кроме Zod | React, `fetch`, даты «сейчас», случайные числа |
| `catalog` | `calc` | React, код приложения |
| `ui` | Ничего из проекта | `calc`, `catalog`, код приложения |
| `db` | Ничего из проекта | Код приложения |
| `web/src` | Все пакеты, кроме `db`; слой FSD — только слои ниже себя | `server/` |
| `web/server` | Все пакеты | Компоненты из `src/` |
| `web/app` | `src/views`, `server` | Бизнес-логику внутри файлов маршрутов |

Слои FSD проверяет Steiger, границы пакетов — зависимости в `package.json`. Каждый файл в `server/` начинается с `import "server-only"`: попытка подключить его в браузерный код ломает сборку. Слой страниц назван `views`, потому что папку `pages` Next.js считает маршрутами.

**Платформенный слой.** `server/platform/` отдаёт три вещи: проверенные переменные окружения, IP клиента из заголовка прокси и запуск работы после ответа. Прод и стейджинг оба работают на Node.js, поэтому реализация одна, а окружения различает переменная `APP_ENV`. API, которые есть только у Vercel, в коде не используются.

**Новый калькулятор — пять файлов, без правки маршрутов**

| Файл | Что в нём |
| --- | --- |
| `packages/calc/src/tools/laminat/index.ts` | Схема ввода, значения по умолчанию, функция расчёта |
| `packages/calc/src/tools/laminat/golden.ts` | Десять эталонных примеров |
| `packages/catalog/src/tools/laminat.ts` | Адрес, категория, заголовки, поля формы, пресеты, связки «дальше по ремонту» |
| `apps/web/content/tools/laminat.md` | Текст под инструментом и вопросы-ответы |
| `apps/web/src/widgets/layout-scheme/laminat.tsx` | Схема раскладки, только если она нужна |

Идентификатор инструмента один на всё: `laminat` — это имя модуля, сегмент адреса, имя файла с текстом и значение `tool` в событиях аналитики. Идентификаторы в коде английские или транслитом, строки интерфейса русские и лежат в `catalog` и `content`.

## 5. Расчётный модуль

Каждый калькулятор — чистая функция: одинаковый ввод всегда даёт одинаковый результат, без сети, времени и случайности. Поэтому один и тот же код считает на сервере при сборке страницы, в браузере, в мини-приложении и в тестах.

**Контракт инструмента**

```ts
export interface ToolModule<I, R extends ToolResult = ToolResult> {
  id: ToolId;                          // 'laminat'
  version: number;                     // растёт при изменении формулы
  input: z.ZodType<I>;                 // схема ввода и допустимые границы
  defaults(ctx: CalcContext): I;       // типовые значения с учётом комнаты и страны
  compute(input: I, ctx: CalcContext): R;
}

export interface CalcContext {
  room?: Room;                         // «Моя комната», если уже введена
  country: 'RU' | 'KZ' | 'BY' | 'KG';
}

export interface ToolResult {
  items: PurchaseItem[];               // что купить: основная позиция и сопутствующие
  summary: Quantity[];                 // промежуточные цифры: площадь, периметр
  cost?: Cost;                         // если введена цена упаковки
  warnings: Warning[];                 // код, уровень, числа для текста
  steps: Step[];                       // «Как посчитано»: формула и подставленные числа
  layout?: Layout;                     // геометрия схемы, если она есть
}

export interface PurchaseItem {
  key: string;                         // 'laminate' | 'underlay' | 'plinth'
  role: 'main' | 'related';
  need: Quantity;                      // сколько нужно по расчёту
  pack: Pack;                          // размер упаковки
  packs: number;                       // сколько упаковок купить, целое
  bought: Quantity;                    // сколько будет куплено
  leftover: Quantity;                  // остаток
  shopQuery?: string;                  // запрос для кнопки «Посмотреть материал»
  nextTool?: ToolId;                   // детальный расчёт этой позиции
}
```

Этот контракт закрывает требования 1, 2, 4, 5, 6, 7 и 15 из стандарта калькулятора. Планировщик складывает `items` нескольких инструментов в один список покупок, ничего не пересчитывая сам.

**Правила расчётов**

| Тема | Правило |
| --- | --- |
| Единицы | Длины внутри модуля — целые миллиметры. Площади и объёмы — в м² и м³. Перевод из метров и сантиметров делает форма |
| Округление | Полная точность до конца расчёта. Упаковки — всегда вверх, через `ceilPacks()` с допуском 1e-9, чтобы 10,0000001 не стало 11 |
| Отображение | Число знаков и формат задаёт интерфейс, не формула |
| Запас | `WasteRule`: процент по умолчанию зависит от метода укладки и формы комнаты; пользователь может заменить |
| Тексты | Модуль возвращает коды и числа: `{ code: 'narrow_last_row', widthMm: 50 }`. Русский текст предупреждений и шагов лежит в `catalog` |
| Нормы | Расход смесей, нормы освещённости, таблицы сечений — данные в `catalog` с полями `source` и `checkedAt` |
| Ошибки | `compute` не бросает исключений на вводе, прошедшем схему. Сомнительный ввод даёт предупреждение, а не отказ |
| Версия | `version` сохраняется в проекте. Если формула изменилась, проект пересчитывается и показывает пометку «расчёт обновлён» |

**Общие блоки, из которых собираются инструменты**

| Блок | Что делает | Кто использует |
| --- | --- | --- |
| `geometry` | Площадь и периметр прямоугольника, Г-образной комнаты и многоугольника; площадь стен за вычетом проёмов | Почти все |
| `packs` | Округление до упаковок, остаток, подбор набора банок с минимальной переплатой | Все с покупкой |
| `waste` | Правила запаса по методу | Пол, плитка, обои, панели |
| `coverage` | Расход на м² × слои × коэффициент основания | Краска, грунтовка, шпаклёвка, штукатурка, клей, затирка |
| `rows` | Раскладка рядами: смещение, подрезка, последний ряд, повторное использование обрезков | Ламинат, кварцвинил, панели, вагонка |
| `grid` | Раскладка сеткой от центра или угла: шов, подрезанные плитки | Плитка |
| `strips` | Полосы из рулона с раппортом и смещением | Обои, линолеум, шторы |
| `frame` | Каркас: профили, подвесы, крепёж по шагу | Гипсокартон, потолок из ГКЛ, обрешётка под панели |
| `power` | Мощность по объёму и поправкам | Радиаторы, кондиционер, тёплый пол, освещение |

**Тесты формул**

1. **Эталонные примеры.** У каждого инструмента файл `golden.ts`: минимум десять записей с вводом, ожидаемым результатом и источником (техлист производителя, ручной расчёт, сверка с конкурентом). Один общий тест прогоняет все инструменты; сборка падает, если примеров меньше десяти.
2. **Инварианты через fast-check.** Для любого допустимого ввода: куплено не меньше, чем нужно; упаковок целое число; при росте площади упаковок не становится меньше; в результате нет `NaN` и бесконечности.
3. **Порог покрытия** для `packages/calc` — 95% строк.
4. **Выгрузка для рецензента.** Команда `pnpm calc:export` собирает эталонные примеры волны в таблицу, которую читает мастер без доступа к коду. Его правки возвращаются как новые примеры.

## 6. Компонент калькулятора и «Моя комната»

Все инструменты рисует один компонент `CalculatorShell`. Инструмент описывается данными в `catalog`, а не отдельной вёрсткой, поэтому 16 требований стандарта реализуются один раз.

**Как страница получает результат**

1. **Сборка.** Сервер берёт инструмент из реестра, вызывает `compute(defaults())` и кладёт в HTML готовый результат по типовым значениям. Поисковик и человек видят числа до загрузки скриптов.
2. **Гидратация.** Первый рендер в браузере повторяет серверный один в один. После монтирования компонент подставляет ввод по приоритету: параметры из адреса, затем «Моя комната», затем сохранённые значения инструмента.
3. **Пересчёт.** Каждое изменение поля сразу вызывает `compute()`. Цель — меньше 5 мс на расчёт; раскладка плитки и ламината идёт через `useDeferredValue`, чтобы ввод не подтормаживал.
4. **Размер.** Страница грузит расчётный модуль только своего инструмента. Планировщик подгружает модули по мере выбора работ.

**Форма описывается данными**

```ts
type FieldDef =
  | { kind: 'length';   name: string; label: string; unit: 'm' | 'cm' | 'mm';
      min: number; max: number; room?: 'length' | 'width' | 'height' }
  | { kind: 'number';   name: string; label: string; min: number; max: number; step?: number }
  | { kind: 'select';   name: string; label: string; options: Option[] }
  | { kind: 'toggle';   name: string; label: string }
  | { kind: 'preset';   label: string; presets: PresetId[] }   // заполняет несколько полей сразу
  | { kind: 'openings' }                                       // список окон и дверей
  | { kind: 'price';    name: string; label: string };         // валюта берётся из страны
```

Поля ввода живут в `packages/ui`. Числовое поле открывает цифровую клавиатуру (`inputMode="decimal"`), принимает запятую и точку, переключает метры и сантиметры; высота зоны нажатия не меньше 48 px.

**Отправка без сервера.** Кнопка «Отправить» кодирует в параметр `s` только поля, которые отличаются от типовых: JSON, затем base64url. Запроса к серверу нет, ссылка работает мгновенно. Тег `canonical` у такой страницы указывает на чистый адрес, поэтому дублей в индексе не появляется. Кнопка «Сохранить» создаёт проект на сервере: он нужен, когда расчётов несколько или к ним будут возвращаться.

**Модель комнаты**

```ts
interface Room {
  shape: 'rect' | 'l' | 'polygon';
  lengthMm: number;
  widthMm: number;
  heightMm: number;
  cut?: { lengthMm: number; widthMm: number };   // вырез для Г-образной комнаты
  points?: [number, number][];                   // произвольный контур, вторая версия планировщика
  openings: { type: 'door' | 'window'; widthMm: number; heightMm: number; count: number }[];
}
```

Поле с привязкой `room` читает и пишет «Мою комнату» напрямую: источник размеров один. Версия в ключе хранилища (`v1`) позволяет менять модель без поломки сохранённых данных: при смене версии запускается функция миграции.

**Событие** `calc_completed` считает сама оболочка: изменены минимум два поля и блок результата был в видимой области 5 секунд. Инструменты про аналитику не знают.

| Служебные | `app/(info)/…/page.tsx` | `/metodika/`, `/o-proekte/`, `/politika/`, `/kontakty/`, `/partneram/` | Статика | Да |

| API | `app/api/**/route.ts` | `/api/projects` | На сервере | Нет |

Служебные файлы Next.js: `sitemap.ts`, `robots.ts`, `manifest.ts`, `not-found.tsx`, `opengraph-image.tsx` для инструментов.

**Правила маршрутизации**

- `trailingSlash: true`: индексируемые адреса заканчиваются косой чертой, как в бизнес-спеке.
- `generateStaticParams` читает реестр; `dynamicParams = false`, поэтому неизвестный адрес сразу отдаёт 404.
- Зарезервированные сегменты первого уровня: `remont`, `spravochnik`, `p`, `embed`, `tg`, `api`. Тест реестра не даёт назвать так категорию.
- В индексируемых страницах нет `cookies()` и `headers()`: они превращают страницу в динамическую. Страна определяется в браузере (раздел 10).
- Адреса категорий: `osnova`, `pol`, `steny`, `plitka`, `potolok`, `elektrika`, `klimat`, `strojmaterialy`, `interer`.

**Состав страницы инструмента, сверху вниз**

1. `H1` и одна строка пояснения.
2. `RoomBar`, форма и результат — на первом экране телефона.
3. Схема раскладки, если есть.
4. Действия и связки «дальше по ремонту».
5. «Как посчитано», источник норм, дата проверки.
6. Текст 300–600 слов и вопросы-ответы из Markdown.
7. Связанные инструменты и ссылка на методику.

Рекламные места заложены компонентом `AdSlot` под результатом и между секциями текста. До этапа 3 он ничего не рендерит; у него задана минимальная высота, чтобы включение рекламы не сдвигало вёрстку. Над результатом места нет.

**Вариации.** Вариация — запись в `catalog`: адрес, заголовки, переопределение типовых значений и свой файл текста. Схема frontmatter требует собственный пример и минимум три вопроса-ответа; без них сборка падает. Так правило из бизнес-спеки проверяется автоматически.

**Тексты.** Файл `content/tools/laminat.md` начинается с frontmatter: `title`, `description`, `h1`, `updatedAt`, `checkedAt`, `example`, `faq[]`. Схему проверяет Zod при сборке. Числа норм в текст вставляются подстановками из `catalog` (`{{norm.underlay.overlap}}`), чтобы текст не расходился с кодом.

**Заголовки ответа**

| Страницы | Кэш | Роботы | Встраивание |
| --- | --- | --- | --- |
| Индексируемые | `max-age=0, must-revalidate` | `index, follow` | Только свой домен и Telegram |
| `/p/[id]` | `private, no-store` | `noindex, nofollow` в теге и в `X-Robots-Tag` | Только свой домен и Telegram |
| `/embed/*` | Как у индексируемых | `noindex` | Любой сайт |
| `/tg/` | Как у индексируемых | `noindex` | Только Telegram |
| Файлы сборки с хэшем | `max-age=31536000, immutable` | — | — |

Сохранённые проекты не закрываются в `robots.txt`: иначе робот не увидит `noindex`. Веб-версия Telegram открывает мини-приложение во фрейме, поэтому `frame-ancestors` разрешает домены Telegram.

CDN на старте нет. HTML отдаёт сам сервер с заголовком `ETag`, поэтому повторный заход получает короткий ответ 304. Caddy сжимает ответы в gzip и zstd.

```ts
  kind: 'rows' | 'grid' | 'strips' | 'points' | 'outline';
```

Движки возвращают `Layout`, а один компонент `LayoutScheme` рисует его в SVG: целые элементы контуром, подрезанные штриховкой. Если элементов больше 2 000, схема упрощается до рядов. - Атомарные операции — SQL-функции: `hit_limit(key, max, window)`, `ai_usage_add(...)`, `project_touch(id)`. Вызываются через `rpc()`.
- `projects.data` проверяется схемой Zod и ограничен 32 КБ. В нём размеры, выбранные материалы и версии формул; личных данных нет.
- Идентификатор проекта — 8 случайных символов без похожих знаков (`0/O`, `1/l`). Перебор закрыт лимитом на чтение.
- Миграции — пронумерованные SQL-файлы в `packages/db/migrations`, применяются Supabase CLI из CI. Типы TypeScript генерируются из схемы и лежат в репозитории.
- Очистка — `pg_cron` раз в сутки: проекты без открытий 12 месяцев, сообщения об ошибках старше года, отработавшие окна лимитов.
- Резервная копия — еженедельный `pg_dump` из GitHub Actions в приватное хранилище, пока проект на бесплатном плане.
- Регион проекта — Франкфурт: ближайший к аудитории из доступных.

**Кто может менять проект.** При создании сервер выдаёт `editToken`; браузер хранит его в localStorage, база — только хэш. Открывший ссылку видит проект и может нажать «Сохранить как свой» — получится копия. В Telegram владельца определяет идентификатор пользователя. Аккаунт для этого не нужен.

**Серверные маршруты**

| Метод и путь | Что делает | Лимит |
| --- | --- | --- |
| `POST /api/projects` | Создаёт проект, возвращает `id` и `editToken` | 20 в час с IP |
| `GET /api/projects/[id]` | Отдаёт проект, отмечает открытие | 120 в минуту с IP |
| `PUT /api/projects/[id]` | Обновляет проект по `editToken` | 60 в минуту |
| `DELETE /api/projects/[id]` | Удаляет проект по `editToken` | 20 в час |
| `POST /api/projects/[id]/copy` | Создаёт копию для нового владельца | 20 в час |
| `POST /api/reports` | Принимает сообщение об ошибке | 5 в час |
| `POST /api/e` | Увеличивает обезличенный счётчик события | 300 в минуту с IP |
| `POST /api/ai/label` | Фото этикетки → параметры материала | Суточный лимит на устройство |
| `POST /api/ai/plan` | Фото плана → комнаты и размеры | Суточный лимит на устройство |

**Общие правила API**

- Тело запроса и ответа проверяются Zod. Ответ один на всё: `{ ok: true, data }` или `{ ok: false, error: { code, message } }`.
- JSON не больше 64 КБ; изображение не больше 4 МБ, браузер заранее уменьшает его до 1600 px по длинной стороне.
- Запросы принимаются только со своего домена: проверяется заголовок `Origin`. Сессионных cookie нет.
- Страница `/p/[id]` читает проект напрямую функцией из `server/db`, без HTTP-запроса к собственному API.
- Каждый маршрут пишет в лог строку: путь, код ответа, длительность. IP и содержимое проекта в лог не попадают.

## 10. Страна, валюта и магазины

Страна — это конфигурация в `catalog`, а не отдельные страницы: набор адресов один, `hreflang` и региональных копий нет. От страны зависят валюта, формат чисел, типовые цены, тарифы и магазины в кнопках.

```ts
interface CountryConfig {
  code: 'RU' | 'KZ' | 'BY' | 'KG';
  currency: 'RUB' | 'KZT' | 'BYN' | 'KGS';
  locale: 'ru-RU' | 'ru-KZ' | 'ru-BY' | 'ru-KG';
  typicalPrices: Record<PriceKey, number>;   // подсказки в полях цены, с датой проверки
  electricityTariff: number;                 // значение по умолчанию для расчётов расхода
  climateRegions: ClimateRegion[];           // поправки для радиаторов и кондиционера
  shops: ShopConfig[];                       // пусто до теста на этапе 3
  adNetwork: 'yan' | 'adsense' | null;
}

interface ShopConfig {
  id: string;
  name: string;
  categories: ToolId[];                      // в каких инструментах показывать
  buildUrl(query: string): string;           // поиск по магазину с партнёрскими параметрами
  adLabel?: { text: string; erid?: string }; // маркировка рекламы, где она обязательна
}
```

**Как определяется страна**

1. Сохранённый выбор пользователя из localStorage.
2. Часовой пояс браузера: `Asia/Bishkek` → KG, `Europe/Minsk` → BY, казахстанские пояса (`Asia/Almaty`, `Asia/Aqtobe`, `Asia/Qyzylorda` и остальные) → KZ.
3. Иначе — Россия. Посетители из других стран тоже получают российскую конфигурацию.

Серверного определения по IP нет: оно потребовало бы базу адресов на сервере, а часового пояса для четырёх стран достаточно.

Переключатель страны стоит в шапке и в подвале. Статический HTML всегда собран с российскими значениями: валюта появляется на экране только после ввода цены, поэтому поисковик видит одинаковый текст для всех стран.

**Деньги.** Суммы форматирует `Intl.NumberFormat` с локалью и валютой страны. Цены хранятся в валюте ввода и не пересчитываются по курсу: проект, созданный в тенге, остаётся в тенге.

**Кнопка «Посмотреть материал».** Ссылку строит `buildUrl()` из позиции списка покупок. У ссылки `rel="sponsored nofollow noopener"`, рядом — пометка рекламы из `adLabel`. Переход считает событие `shop_clicked` с инструментом, позицией и магазином. Серверного редиректа нет: это лишний запрос и лишняя точка отказа. До этапа 3 массив `shops` пуст и кнопка не рисуется.

## 11. Планировщик и проекты по ссылке

Планировщик не содержит своих формул: он вызывает те же модули `calc` и складывает их позиции в один список. В проекте хранится только ввод; результат каждый раз пересчитывается, поэтому исправление формулы доходит до старых проектов.

```ts
interface ProjectData {
  schemaVersion: 1;
  title?: string;
  country: 'RU' | 'KZ' | 'BY' | 'KG';
  rooms: ProjectRoom[];                 // в первой версии ровно одна
  master?: MasterSheet;                 // режим мастера, этап 3
}

interface ProjectRoom {
  id: string;
  name: string;
  room: Room;
  works: ProjectWork[];
}

interface ProjectWork {
  tool: ToolId;
  toolVersion: number;                  // версия формулы на момент сохранения
  input: Record<string, unknown>;       // только поля, отличные от типовых
  prices?: Record<string, number>;      // цена упаковки по ключу позиции
}
```

**Как собирается список покупок**

1. Пользователь вводит комнату и отмечает работы. Список работ и их порядок берутся из `catalog`.
2. Для каждой работы вызывается `defaults(ctx)` с этой комнатой и показывается короткая форма: только поля с флагом `planner`.
3. `compute()` каждой работы возвращает `items`.
4. `mergeItems()` из `calc` объединяет одинаковые позиции с одинаковой упаковкой и сортирует их по порядку работ: черновые, затем чистовые.
5. Каждая строка списка ведёт в детальный расчёт инструмента с теми же значениями.

**Сохранение**

- Черновик всегда лежит в localStorage (`umnyaut:planner:draft`): закрытая вкладка ничего не теряет.
- Первое нажатие «Сохранить» создаёт проект на сервере и выдаёт ссылку `/p/<id>`. Дальше изменения сохраняются сами, с задержкой 2 секунды.
- Страница `/p/<id>` рендерится на сервере уже со списком покупок. Владелец с `editToken` получает режим правки, остальные — просмотр и кнопку «Сохранить как свой».
- Заголовок и превью ссылки собираются из размеров: «Список покупок: комната 19,8 м²». Имён и телефонов там нет.
- Повторным открытием считается открытие позже чем через час после предыдущего. Метрику возвратов за 7 дней считает SQL-запрос по `project_opens`.

**Вывод результата**

| Действие | Реализация | Версия |
| --- | --- | --- |
| Ссылка | `/p/<id>` | Первая |
| Текст для мессенджера | `formatAsText(project)`: список позиций и сумма простым текстом, через `navigator.share` или копирование | Первая |
| Печать | Отдельные стили `@media print`, без шапки и кнопок | Первая |
| PDF | Тот же печатный макет через «Сохранить как PDF» в браузере | Вторая |
| Таблица | CSV, собранный в браузере | Вторая |

Отдельного сервиса генерации PDF нет: ему нужен браузер на сервере, а печатный макет делается в любом случае.

**Версии планировщика в технических терминах**

| Версия | Что добавляется в коде |
| --- | --- |
| Первая, этап 2 | `ProjectData` с одной комнатой, шесть работ первой волны, `mergeItems`, API проектов, страница `/p/[id]` |
| Вторая, этап 3 | Несколько элементов в `rooms`, контур `polygon`, работы второй волны, CSV и PDF, ввод комнат из `POST /api/ai/plan` |
| Третья, этап 4 | Сверка со сметой подрядчика (раздел 13), кнопки магазинов в строках списка |

Смена `schemaVersion` сопровождается функцией миграции в `packages/calc/project`: сервер отдаёт данные как есть, браузер приводит их к текущей схеме при открытии.

## 12. Telegram-бот

Бот — это один серверный маршрут и те же страницы сайта, открытые внутри Telegram. Отдельного приложения и отдельной вёрстки нет.

| Часть | Реализация |
| --- | --- |
| Бот | grammY в режиме вебхука на `POST /api/tg/webhook`. Запрос принимается только с секретным заголовком, заданным при регистрации вебхука |
| Мини-приложение | Вход `/tg/`: «Мои расчёты», популярные инструменты, планировщик. Дальше открываются обычные страницы инструментов |
| Подстройка интерфейса | `TelegramProvider` видит `Telegram.WebApp.initData`, скрывает шапку, подвал и рекламные места, берёт цвета темы Telegram в CSS-переменные, включает кнопку «Назад» и главную кнопку «Сохранить» |
| Авторизация | Браузер шлёт `initData` в заголовке запроса; сервер проверяет подпись токеном бота и свежесть `auth_date` (не старше суток). Cookie и паролей нет |
| «Мои расчёты» | Проект, сохранённый внутри Telegram, получает `tg_user_id`. Список отдаёт `GET /api/tg/calcs` |
| Глубокие ссылки | `t.me/<бот>?startapp=<id>` открывает проект сразу в мини-приложении |

**Команды и сценарии**

| Сценарий | Что делает бот | Этап |
| --- | --- | --- |
| `/start` | Приветствие и кнопки: открыть планировщик, мои расчёты, популярные инструменты | 2 |
| `/my` | Последние пять проектов кнопками | 2 |
| Ссылка на проект в чате | Отвечает кнопкой «Открыть в мини-приложении» | 2 |
| Фото этикетки или плана | Скачивает файл, вызывает распознавание, отвечает найденными параметрами и кнопкой инструмента с подставленными значениями | 3 |
| Смета клиенту | Кнопка «Переслать» открывает выбор чата со ссылкой на проект | 3 |

**Правила**

- Бот ничего не считает: он выдаёт кнопки и ссылки, расчёт идёт в `calc` на странице.
- Вебхук отвечает Telegram сразу. Долгая работа — скачивание фото, вызов ИИ — уходит в фоновую задачу платформенного слоя.
- Код мессенджера лежит за интерфейсом `MessengerAdapter` в `server/messenger/`: отправить сообщение, отправить ссылку на проект, разобрать входящее. Второй мессенджер подключается новой реализацией без правки расчётов и планировщика.
- У тестового окружения свой бот и свой токен.
- События аналитики из мини-приложения получают параметр `source: 'tg'`.
- Рекламных мест в мини-приложении нет.

Мини-приложение загружает страницы с того же домена и работает везде, где открывается сайт. В России его ограничивает сам Telegram. Это согласуется с бизнес-спекой: бот — основной канал возврата для Казахстана, Беларуси и Кыргызстана.

## 13. ИИ-функции

ИИ вызывается только с сервера и только чтобы превратить фото или текст в параметры формы. Распознавание этикетки стоит около 0,3 ₽ за запрос, поэтому месячный потолок в 1–3 тыс. ₽ покрывает несколько тысяч распознаваний.

**Конвейер, один для всех функций**

1. **Браузер** уменьшает фото до 1280 px по длинной стороне и пересохраняет в JPEG. Это снижает цену запроса и убирает из файла геометку и данные камеры.
2. **Сервер** проверяет суточный лимит устройства и месячный бюджет в `ai_usage`.
3. **Провайдер** получает изображение, короткую инструкцию и схему ответа. Инструкция требует возвращать только напечатанное на упаковке и `null` для всего, чего не видно.
4. **Сервер** проверяет ответ схемой Zod, записывает расход и возвращает поля с отметкой уверенности.
5. **Браузер** показывает найденные значения на экране подтверждения. Человек правит и подтверждает, после чего работает обычная формула.

Фото не сохраняется и не попадает в логи: оно живёт в памяти одного запроса.

```ts
interface VisionProvider {
  extract<T>(request: {
    images: Uint8Array[];
    instruction: string;
    schema: z.ZodType<T>;
    tier: 'fast' | 'accurate';
  }): Promise<{ data: T; usage: { inputTokens: number; outputTokens: number; costMicroUsd: number } }>;
}
```

**Модели и цена запроса**

| Функция | Модель | Вход, токенов | Выход, токенов | Цена запроса | Бесплатно в сутки |
| --- | --- | --- | --- | --- | --- |
| Фото этикетки | Claude Haiku 4.5 | ≈ 2 500 | ≈ 300 | ≈ $0,004 | 5 |
| Описание словами | Claude Haiku 4.5 | ≈ 700 | ≈ 300 | ≈ $0,002 | 10 |
| План квартиры по фото | Claude Sonnet 5.5 | ≈ 4 000 | ≈ 800 | ≈ $0,016 | 2 |
| Проверка сметы, до 5 страниц | Claude Sonnet 5.5 | ≈ 12 000 | ≈ 2 500 | ≈ $0,05 | 1, дальше платный пакет |

Цены моделей взяты из [прайса Anthropic](https://platform.claude.com/docs/en/about-claude/pricing): Haiku 4.5 — $1 за миллион входных токенов и $5 за миллион выходных, Sonnet 5.5 — $2 и $10. Число токенов — моя оценка; точные значения снимаются из поля `usage` на тестовом наборе. Визуализация отделки не проектируется до решения об эксперименте: это генерация изображений и другой провайдер.

**Лимиты и защита бюджета**

| Механизм | Как работает |
| --- | --- |
| Суточный лимит | Счётчик по идентификатору устройства из localStorage, в Telegram — по пользователю |
| Второй контур | Суточный потолок на IP, чтобы очистка хранилища не обнуляла лимит |
| Месячный бюджет | Сумма `cost_microusd` за месяц. При превышении кнопки ИИ скрываются до следующего месяца |
| Аварийный выключатель | Переменная окружения `AI_ENABLED` отключает все функции без деплоя |
| Таймаут | 20 секунд на запрос, одна повторная попытка. При отказе показывается обычная форма |

**Проверка качества до выпуска**

- Тестовый набор: 30 реальных фото этикеток и 10 планов, размеченных вручную.
- Порог выпуска: не меньше 90% полей этикетки распознаны верно; неверное поле с высокой уверенностью — блокирующая ошибка.
- На наборе сравниваются быстрая и точная модели; в работу идёт самая дешёвая из прошедших порог.
- В продакшене качество показывает доля `ai_corrected` к `ai_used` по каждой функции.

Форма всегда работает без ИИ. Кнопка «Сфотографировать этикетку» стоит рядом с пресетами и не закрывает поля.

## 14. SEO и аналитика

Всё, что нужно поисковику, генерируется из реестра инструментов, а не пишется руками на каждой странице. Все события аналитики проходят через одну типизированную функцию.

**Техническое SEO**

| Элемент | Реализация |
| --- | --- |
| Мета-теги | `generateMetadata` берёт `title`, `description` и `h1` из frontmatter. Заголовок до 65 знаков, описание до 160; сборка предупреждает о превышении |
| Canonical | Абсолютный адрес без параметров на каждой странице. Страница с `?s=` указывает на чистый адрес |
| Разметка JSON-LD | `WebApplication` на инструменте, `FAQPage` на блоке вопросов, `BreadcrumbList` на инструменте и категории, `Organization` и `WebSite` на главной |
| Карта сайта | `sitemap.ts` из реестра: только индексируемые страницы, `lastmod` — дата последней правки текста или формулы |
| `robots.txt` | Закрыт только `/api/`. Для Яндекса — `Clean-param: s`, чтобы адреса с расчётом не считались отдельными страницами |
| Индексация | После выкладки скрипт CI сравнивает карту сайта с предыдущей и отправляет новые и изменённые адреса через IndexNow. Google узнаёт о них из карты сайта в Search Console |
| Редиректы | `www` → без `www`, `http` → `https`. Карта 301-редиректов для переименованных инструментов лежит в `catalog` |
| Картинка для соцсетей | На старте одна общая. Генерация под каждый инструмент — отдельная задача после запуска |
| Перелинковка | Хлебные крошки, связки «дальше по ремонту», связанные инструменты, список категорий в подвале |

**Проверка серверного HTML.** Тест в CI открывает собранный HTML каждой индексируемой страницы без JavaScript и проверяет: есть `title`, один `H1`, `canonical`, текст и числа результата. Это автоматический страж главного условия бизнес-спеки: поисковику всегда есть что отдавать.

**События**

```ts
  ai_used:           { feature: AiFeature };

  error_reported:    { tool: ToolId };
  js_error:          { tool?: ToolId };
};

track('calc_completed', { tool: 'laminat', fieldsChanged: 3 });
```

| Тема | Решение |
| --- | --- |
| Куда уходят события | Два адаптера: свой обезличенный счётчик работает всегда, Яндекс Метрика — после согласия. GA4 добавляется третьим без правки компонентов |
| Общие параметры | `track()` сам добавляет страну, источник (`web`, `tg`, `embed`), категорию и вариацию |
| Адрес в хитах | В Метрику передаётся адрес без параметра `s`, иначе отчёты распадутся на тысячи адресов |
| Загрузка Метрики | Только после нажатия «Принять» и после отрисовки страницы. На скорость первого экрана не влияет |
| Вебвизор | Поля режима мастера с именами и телефонами помечены классом, который исключает их из записи |
| Личные данные | В события попадают только идентификаторы инструментов и числа. Размеры, цены и тексты не передаются |

**Согласие на cookie: запускаемся в строгом режиме.** Юрист для этого не нужен: строгий режим он может только смягчить. Это самый осторожный вариант, а не юридическое заключение.

| Что | Как делаем |
| --- | --- |
| Метрика и Вебвизор | Скрипт не загружается, пока человек не нажал «Принять». До этого cookie Яндекса не ставятся |
| Баннер | Узкая полоса внизу экрана, результат не закрывает. Две равные кнопки «Принять» и «Отклонить», ссылка на политику. Без заранее отмеченных галочек и без стены поверх сайта |
| Выбор | Хранится в localStorage. Сменить его можно ссылкой «Настройки cookie» в подвале. После отказа баннер не показывается 6 месяцев |
| Что работает без согласия | Всё: расчёты, «Моя комната», сохранение проектов. Это хранение нужно самой функции; оно описано в политике |
| Свои счётчики | Обезличенные итоги по событиям считаются всегда: в них нет cookie, идентификаторов и IP |
| Мини-приложение Telegram | Тот же баннер и тот же выбор |
| Реклама | До этапа 3 рекламных cookie нет. Перед первым рекламным блоком в баннер добавляется отдельная категория |

**Обезличенные счётчики.** Главная метрика не должна зависеть от доли согласившихся. Поэтому `track()` дублирует событие на свой сервер через `navigator.sendBeacon('/api/e')`: имя события, инструмент, страна, источник. Сервер увеличивает число в `events_daily` и больше ничего не сохраняет. По этой таблице считаются полезные расчёты в неделю. Метрика даёт воронку от поиска и записи Вебвизора по тем, кто согласился.

**Что остаётся юристу.** Консультация стоит в роудмапе на февраль 2027, до первого рекламного блока. Вопросы к ней: можно ли загружать Метрику до согласия; обязанности оператора данных в каждой из четырёх стран; рекламные cookie РСЯ и AdSense; где хранить шапку сметы с именами и телефонами.

**Отчёты.** Команда `pnpm report:weekly` собирает данные из API Метрики, Вебмастера и Search Console в одну таблицу Markdown: показы, клики, позиция, полезные расчёты и действия по каждому инструменту. Долю повторно открытых проектов считает SQL-запрос. Это задача этапа 2; до неё хватает интерфейсов самих сервисов.

## 15. Качество: производительность, тесты, CI/CD

Каждый PR проходит одну цепочку проверок. Стейджинг работает на Vercel, прод — в Docker на VPS, поэтому образ для прода собирается и проходит дымовой тест уже на PR: разница между окружениями ловится до выпуска.

**Бюджет производительности.** Измеряется на странице инструмента, мобильный профиль Lighthouse.

| Метрика | Порог |
| --- | --- |
| LCP | до 2,0 с |
| INP | до 200 мс |
| CLS | до 0,05 |
| JavaScript первого экрана | до 150 КБ в gzip |
| CSS | до 15 КБ в gzip |
| Шрифты | не больше двух файлов, со своего домена, с кириллическим подмножеством |
| Сторонние домены до взаимодействия | ни одного; Метрика грузится после согласия |
| Оценки Lighthouse | производительность от 90, SEO 100, доступность от 95 |

Доступность входит в стандарт: у каждого поля есть подпись, форма проходится с клавиатуры, блок результата объявлен как `aria-live="polite"`, контраст не ниже AA.

**Тесты**

| Уровень | Инструмент | Что проверяет |
| --- | --- | --- |
| Формулы | Vitest, fast-check | Эталонные примеры и инварианты (раздел 5) |
| Реестр и тексты | Vitest | У каждого инструмента есть модуль, запись в реестре, текст и десять примеров; адреса уникальны; связки ведут на существующие инструменты; frontmatter проходит схему |
| Компоненты | Vitest, Testing Library | Числовое поле: запятая, пустое значение, вставка из буфера. Приоритет источников ввода в оболочке |
| API | Vitest с локальным Supabase в Docker | Создание и правка проекта, `editToken`, лимиты, подпись Telegram |
| Серверный HTML | Скрипт | Страницы без JavaScript содержат заголовки и числа результата (раздел 14) |
| Сквозные | Playwright, экран телефона | Пять сценариев: расчёт ламината; перенос комнаты в плинтус; сохранить и открыть проект; открыть ссылку с `?s=`; отправить сообщение об ошибке |
| Производительность | Lighthouse CI | Пороги из таблицы выше на главной, инструменте и планировщике |

**Цепочка CI/CD**

| Ветка | Куда выкладывается | Когда |
| --- | --- | --- |
| Ветка задачи | Превью на Vercel, свой адрес на каждый PR | Каждый коммит в PR |
| `develop` | Стейджинг на Vercel, `staging.umnyaut.com` | Слияние PR в `develop` |
| `main` | Прод на VPS, `umnyaut.com` | Слияние PR из `develop` в `main` |

1. **PR в `develop`:** установка с кэшем pnpm → Biome, Steiger, `tsc` → тесты → `next build` → сборка Docker-образа и дымовой тест контейнера → Playwright и Lighthouse против превью на Vercel.
2. **Слияние в `develop`:** Vercel выкладывает стейджинг; миграции применяются к базе `umnyaut-dev`.
3. **PR из `develop` в `main`:** те же проверки и ручной проход стейджинга на телефоне.
4. **Слияние в `main`:** образ с тегом коммита уходит в GitHub Container Registry → миграции применяются к `umnyaut-prod` → сервер по SSH забирает образ и поднимает новый контейнер рядом со старым → после проверки `/api/health` Caddy переключает трафик → дымовой тест с внешнего адреса → отправка адресов в IndexNow.
5. **Откат:** одна команда запускает образ предыдущего тега. Миграции пишутся обратно совместимыми, чтобы старая версия кода работала с новой схемой.
6. **По расписанию:** проверка доступности раз в сутки, резервная копия базы и проверка ссылок в текстах раз в неделю, обновление зависимостей через Renovate раз в месяц.

Turborepo пересобирает и тестирует только затронутые пакеты: правка текста не запускает тесты формул.

**Окружения**

| Окружение | Ветка | Где работает | База | Бот |
| --- | --- | --- | --- | --- |
| Локальное | — | `localhost` | Supabase в Docker | Тестовый, через туннель |
| Превью | PR | Vercel, адрес на каждый PR | `umnyaut-dev` | — |
| Стейджинг | `develop` | Vercel, `staging.umnyaut.com` | `umnyaut-dev` | Тестовый |
| Прод | `main` | VPS, `umnyaut.com` | `umnyaut-prod` | Боевой |

Бесплатный план Supabase допускает два активных проекта — ровно `dev` и `prod`. Всё, что не прод, определяется по `APP_ENV`: ответы идут с `X-Robots-Tag: noindex`, Метрика и свои счётчики выключены, у ИИ отдельный маленький бюджет.

**Сервер**

| Тема | Решение |
| --- | --- |
| Конфигурация | 2 vCPU, 4 ГБ памяти, 40 ГБ SSD, Ubuntu LTS. Страна и провайдер выбираются проверкой из раздела 18 |
| Состав | Docker Compose: контейнер `web` (Next.js standalone на Node.js 24) и контейнер `caddy` |
| TLS и сжатие | Caddy сам выпускает и продлевает сертификаты, сжимает ответы, ставит заголовки безопасности |
| Состояние | Данных на сервере нет: база в Supabase, образы в реестре, настройки в репозитории. Сервер пересоздаётся скриптом из `infra/` примерно за час |
| Сборка | Образ собирается в GitHub Actions, а не на сервере: память сервера рассчитана на работу, не на сборку |
| Доступ | Вход только по SSH-ключу, отдельный пользователь для выкладки, файрвол открывает порты 22, 80 и 443 |
| Обновления | Автоматические обновления безопасности ОС, перезагрузка в ночное окно |
| Логи | Логи контейнеров с ротацией. В журнале Caddy IP обрезается до подсети, журнал хранится 7 дней |
| Перезапуск | Docker поднимает упавший контейнер сам; проверка здоровья встроена в `compose.yml` |

**Секреты и настройки.** `APP_ENV`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_API_ROOT`, `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `AI_ENABLED`, `AI_MONTHLY_BUDGET_USD`, `METRIKA_ID`, `INDEXNOW_KEY`. Для стейджинга они заданы в настройках проекта Vercel, для прода — в файле окружения на сервере, доступном только пользователю выкладки. В GitHub хранятся SSH-ключ выкладки и токен реестра; в репозитории лежит только `.env.example`. Схема Zod проверяет окружение при старте: без нужной переменной сервер не запускается.

**Мониторинг**

- Внешняя проверка каждые 5 минут открывает `/api/health` и страницу инструмента с узлов в России и Казахстане. Сбой приходит сообщением в Telegram.
- Отдельное оповещение — когда на диске остаётся меньше 20% места или контейнер перезапустился.
- Серверные ошибки и длительность запросов пишутся в лог контейнера одной строкой JSON на запрос.
- Ошибки браузера уходят в свой счётчик событием `js_error` с именем инструмента. Отдельный сервис ошибок на старте не подключаем.

**Инструмент считается готовым,** когда выполнены требования стандарта, есть десять эталонных примеров и текст, пройдены пороги Lighthouse, события приходят в Метрику, а страница проверена руками на настоящем телефоне.

## 16. Безопасность и персональные данные

До режима мастера сервис почти не хранит личных данных: в базе размеры комнат и идентификаторы Telegram. Первые настоящие персональные данные — имя и телефон в шапке сметы на этапе 3, и к этому моменту должны работать удаление и ответ юриста о месте хранения.

**Какие данные где лежат**

| Данные | Где | Срок | Личные |
| --- | --- | --- | --- |
| Размеры, материалы, цены | localStorage; таблица `projects` | 12 месяцев с последнего открытия | Нет |
| Обезличенные итоги по событиям | `events_daily` | Бессрочно | Нет |
| Выбор в баннере cookie | localStorage | До смены выбора | Нет |
| Идентификатор Telegram | `tg_users` | До команды `/forget` или 24 месяца без активности | Да |
| Идентификатор устройства для лимитов ИИ | localStorage; `ai_usage` | 90 дней | Псевдоним |
| IP для лимитов запросов | Память процесса; `rate_limits`, только хэш с суточной солью | Сутки | Псевдоним |
| IP в журнале веб-сервера | Журнал Caddy, адрес обрезан до подсети | 7 дней | Псевдоним |
| Фото для распознавания | Память одного запроса | Не хранится | Может содержать |
| Cookie Метрики, записи Вебвизора | На стороне Яндекса, только после согласия | По правилам Метрики | Да |
| Имя и телефон мастера, имя клиента (этап 3) | `projects.data.master` | Как у проекта; владелец удаляет сам | Да |

**Меры защиты**

| Угроза | Мера |
| --- | --- |
| Утечка ключей | Секреты только на сервере; `server-only` ломает сборку при импорте серверного кода в браузер; публичный ключ Supabase в браузер не отдаётся |
| Прямой доступ к базе | RLS без политик на всех таблицах |
| Перебор проектов и спам | Лимиты из раздела 9, счётчик в памяти процесса, скрытое поле-ловушка в форме сообщения об ошибке |
| XSS | Название проекта, строки работ и шапка сметы выводятся только как текст. HTML из Markdown проходит очистку, хотя тексты наши |
| Вредный файл | Принимаются JPEG, PNG и WebP по сигнатуре файла, до 4 МБ; файл не сохраняется |
| Инструкции внутри фото или сметы | Ответ модели ограничен схемой, числа проверяются на допустимые границы, текст ответа не исполняется и не вставляется как HTML |
| Подделка запросов Telegram | Секретный заголовок вебхука, проверка подписи `initData` |
| Встраивание чужим сайтом | `frame-ancestors` по таблице раздела 7 |
| Уязвимые зависимости | Renovate, `pnpm audit` в CI, у `calc` одна зависимость |
| Потеря базы | Еженедельная копия; пробное восстановление раз в квартал |

Заголовки на всех ответах: `Content-Security-Policy` со списком разрешённых источников (свой домен, Метрика, Telegram), `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.

**Сервер.** Вход только по SSH-ключу, файрвол, автоматические обновления безопасности, приложение в контейнере без прав суперпользователя. Данных на сервере нет, поэтому после взлома он не лечится, а пересоздаётся; секреты при этом перевыпускаются. Настройки описаны в разделе 15.

**Удаление данных**

- Владелец проекта удаляет его кнопкой: `DELETE /api/projects/[id]` с `editToken`.
- Команда `/forget` в боте удаляет запись пользователя и отвязывает его проекты.
- Запрос по почте из политики конфиденциальности закрывается теми же двумя операциями вручную.

**Политика конфиденциальности** описывает ровно эту таблицу: что собирается, зачем, где хранится и сколько. Страница входит в этап 1 вместе с баннером согласия.

**Вопрос юристу до этапа 3.** База находится во Франкфурте. Допустимо ли хранить там имена и телефоны клиентов из России, или шапку сметы нужно держать только на устройстве мастера и подставлять в документ при отправке. Технически готовы оба варианта: блок `master` отделён от остальных данных проекта.

## 17. Поздние этапы: режим мастера, аккаунты, платежи, виджет

Ни одна из поздних функций не требует перестройки: каждая добавляет таблицы и маршруты, а расчётный модуль не трогает. Детальная спека по каждой пишется перед её этапом; здесь зафиксировано, что должно быть заложено уже сейчас.

| Функция | Этап | Новое в коде | Новое в базе |
| --- | --- | --- | --- |
| Лёгкий режим мастера | 3 | Блок `master` в проекте, вид «для клиента» на `/p/<id>`, печатный макет сметы | Ничего: данные лежат в `projects.data` |
| Платный режим мастера | 4 | Supabase Auth, кабинет `/kabinet/`, проверка тарифа на сервере | `accounts`, `price_lists`, `clients`, `subscriptions`, поле `projects.account_id` |
| Платежи | 4 | Интерфейс `PaymentProvider`, маршрут вебхука | `payments` |
| Виджет | 4 | Загрузчик `embed.js`, настройки через атрибуты | `widgets` для платной версии |
| Проверка сметы | 4 | `POST /api/ai/estimate`, экран сопоставления строк | `ai_credits` для платных пакетов |
| Заявки на услуги, спонсорские пресеты | 4 и позже | Конфигурация в `catalog` по образцу магазинов | Ничего |

**Лёгкий режим мастера**

```ts
interface MasterSheet {
  header?: { masterName?: string; masterPhone?: string; clientName?: string };
  works: {
    id: string;
    title: string;                               // «Укладка ламината»
    unit: 'm2' | 'm' | 'pcs' | 'fixed';
    qtyFrom?: { roomId: string; measure: 'floor' | 'walls' | 'ceiling' | 'perimeter' };
    qty: number;                                 // подставляется из комнаты, можно изменить
    price: number;                               // цена за единицу в валюте проекта
  }[];
}
```

Объём работы берётся из размеров комнаты через `qtyFrom` и пересчитывается при их изменении. Итог сметы — материалы из `mergeItems` плюс сумма работ. Условие перехода к платной версии (от 10% проектов со строками работ) считается одним SQL-запросом по `projects.data`.

**Аккаунты.** Вход — код на почту через Supabase Auth; внутри Telegram — по проверенному `initData`, без пароля. Сессия хранится в cookie с флагом `httpOnly` и проверяется на сервере. Правило «браузер не ходит в базу» сохраняется. Кабинет рендерится на сервере и закрыт от индексации. С первым платящим пользователем Supabase переводится на платный план: проект перестаёт засыпать и получает штатные резервные копии.

**Платежи.** Провайдер не выбран: он зависит от проверки эквайринга ИП, срок которой — до апреля 2027. Код зависит только от интерфейса: создать оплату, принять вебхук, отменить подписку. Статус подписки хранится у нас и обновляется только вебхуком с проверкой подписи. Запасной путь для оплаты внутри бота — Telegram Stars; условия вывода нужно проверить вместе с эквайрингом.

**Виджет.** Сайт-партнёр вставляет одну строку: тег `script` с атрибутами `data-tool`, `data-country`, `data-accent`. Загрузчик весит до 2 КБ, создаёт фрейм с `/embed/<tool>` и подгоняет его высоту через `postMessage`. Ссылка «Расчёт: UmnyAut» добавляется на страницу партнёра обычным тегом `a` снаружи фрейма: только так она работает как ссылка для поисковика. В платной версии ссылки нет, цвета и пресеты берутся из таблицы `widgets`, а `frame-ancestors` ограничен доменами клиента.

**Проверка сметы.** Модель превращает фото или PDF в строки «название, единица, количество». Пользователь подтверждает, какой позиции нашего списка соответствует каждая строка. Сравнение объёмов делает обычный код: расхождение больше порога подсвечивается. Цены на первом шаге не сверяются, как решено в бизнес-спеке.

**Что закладываем уже на этапе 1, чтобы не переделывать**

- В `ProjectData` есть необязательный блок `master` и версия схемы.
- Источник события (`web`, `tg`, `embed`) передаётся с первого дня.
- Макет `/embed/` существует как облегчённая оболочка без шапки и рекламы.
- Серверный код обращается к базе только через функции `server/db`, поэтому появление `account_id` — правка в одном месте.

## 18. Риски и открытые вопросы

Хостинг решён: прод на VPS в СНГ, стейджинг на Vercel, Cloudflare не используем. Осталось выбрать страну и провайдера сервера, и это делается замером до Oct 21, 2026, а не по описанию тарифа.

**Решено 7 октября 2026**

| Вопрос | Решение | Где в спеке |
| --- | --- | --- |
| Хостинг прода | VPS в СНГ, ветка `main` | Разделы 2 и 15 |
| Стейджинг | Vercel, ветка `develop`, превью на каждый PR | Раздел 15 |
| Cloudflare | Не используем | — |
| Cookie | Запуск в строгом режиме, без ожидания юриста | Раздел 14 |

**Что должен уметь сервер**

| Проверяем | Почему это не очевидно |
| --- | --- |
| Сайт открывается из России, Казахстана, Беларуси и Кыргызстана | С июня 2025 российские провайдеры режут трафик части зарубежных сетей: названы Cloudflare, Hetzner, DigitalOcean и OVH ([Хабр](https://habr.com/ru/news/922532/)). Попал ли под ограничения конкретный провайдер, показывает только замер |
| С сервера доступен Anthropic API | В [списке поддерживаемых стран](https://www.anthropic.com/supported-countries) есть Казахстан и Кыргызстан. Для сервера в России или Беларуси доступ нужно проверить отдельно |
| С сервера доступны Telegram Bot API и Supabase | Через сервер идут вебхук и ответы бота и все запросы к базе |
| Тариф можно оплатить | Картой или со счёта ИП в Кыргызстане |

Первый кандидат — сервер в Казахстане или Кыргызстане: для него вопрос только в доступности из России. Сервер в России даёт лучшую связь с российскими посетителями, но ставит под вопрос ИИ и бота.

**Проверка сервера**

1. Взять у одного-двух провайдеров младший тариф с почасовой или помесячной оплатой.
2. Развернуть на нём тестовую страницу инструмента с реальным весом: тот же Docker и Caddy из `infra/`.
3. Открыть её из России на четырёх мобильных операторах и двух-трёх проводных провайдерах, минимум в двух регионах. Проще всего попросить пять-шесть человек прислать снимок экрана и время загрузки.
4. Повторить из Казахстана, Беларуси и Кыргызстана.
5. Проверить ответ сервера в Яндекс Вебмастере и Search Console: роботы получают страницу целиком.
6. С сервера отправить по одному запросу в Supabase, Anthropic API и Telegram Bot API.
7. Критерий: страница полностью загружается меньше чем за 5 секунд на каждом подключении и все три исходящих запроса проходят.

**Если ни один сервер не проходит все пункты.** Сайт остаётся там, где лучше доступность для посетителей. Запросы к ИИ и Telegram идут через второй, самый дешёвый сервер-посредник в стране, где они доступны. Код для этого менять не нужно: адреса обоих API заданы переменными `ANTHROPIC_BASE_URL` и `TELEGRAM_API_ROOT`.

**Риски**

| Риск | Вероятность | Что делаем |
| --- | --- | --- |
| Провайдер сервера попадает под ограничения у российских операторов | Средняя | Замер до покупки; мониторинг с узлов в России; сервер без данных переезжает к другому провайдеру за час |
| Один сервер — одна точка отказа | Средняя | Проверка каждые 5 минут, автоперезапуск контейнера, скрипт пересоздания. Простой до часа допустим: платных пользователей до этапа 4 нет |
| На Vercel работает, на VPS ломается | Средняя | Docker-образ собирается и проверяется в CI на каждом PR; в коде нет API, которые есть только у Vercel |
| Сервер отнимает время на обслуживание | Средняя | Два контейнера, автообновления ОС, никакой базы на сервере. Ориентир — час в месяц |
| Без CDN страницы грузятся медленнее | Низкая | Все четыре страны рядом, страница лёгкая. CDN с узлами в СНГ ставится перед Caddy позже |
| Условие Vercel Hobby о некоммерческих проектах | Низкая | На стейджинге нет рекламы и платежей. Запасной путь — второй контейнер на VPS или план Pro |
| Объём этапа 1 при 8–10 часах в неделю | Высокая | Порядок работ из раздела 19; схемы раскладки могут уйти во вторую волну, как разрешает бизнес-спека |
| Расхождение серверного и браузерного рендера при подстановке комнаты | Средняя | Первый рендер повторяет серверный; сквозной тест на перенос комнаты |
| Ошибки округления в формулах | Средняя | Целые миллиметры, `ceilPacks` с допуском, проверка инвариантов |
| Supabase: сон бесплатного проекта; есть [сообщения](https://github.com/Kutyga/color-palette-app/pull/35), что часть российских мобильных операторов не пропускает `*.supabase.co` | Низкая | Браузер к Supabase не обращается; ежедневная проверка доступности будит проект; платный план с первым платящим пользователем |
| Перерасход на ИИ | Низкая | Суточные лимиты, месячный бюджет, выключатель |
| Требования к месту хранения персональных данных | Средняя | Вопрос юристу до этапа 3; блок `master` отделяем |
